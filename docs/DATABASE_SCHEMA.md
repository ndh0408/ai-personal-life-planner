# LifeOS AI — Database Schema

The schema is defined in [`apps/api/prisma/schema.prisma`](../apps/api/prisma/schema.prisma).
This doc is the narrative companion: what each model is for, why the column
shapes are what they are, and which queries the indexes are protecting.

## Conventions

- **IDs** are `cuid()` strings everywhere. No numeric ids, no UUIDs.
- **Money** is `Decimal @db.Decimal(18, 2)`. Never `Float` (rounding errors),
  never `Int` (locks us out of forex). Precision 18 / scale 2 covers VND up
  to 10¹⁶ and leaves headroom for 2 fractional digits.
- **Soft delete** lives only on entities with audit value or recovery need:
  `Wallet`, `Expense`, `Income`, `Task`. Everything else is hard-delete.
  Application queries that filter "live" rows must include `deletedAt: null`.
- **User-scoping**: every entity owned by a user has a `userId` column with
  `onDelete: Cascade`. Account deletion → cascade through every table.
- **Indexes**: every `userId` is indexed; date-range entities also get a
  composite `(userId, <dateColumn>)`; status-filtered entities also get
  `(userId, status)`.
- **Time semantics**: `DateTime` is UTC by default. Wall-clock-only fields
  (e.g. `usualWakeTime`, `quietHoursStart`) are kept as `String "HH:mm"` so
  there is no implicit timezone conversion.
- **JSON columns** (`mainGoals`, `parsedActions`, `evidence`) are typed as
  `Json` — schemas live in `@lifeos/shared` so the API and mobile parse them
  the same way.

## Models at a glance

### Identity

| Model | Purpose | Key invariants |
|---|---|---|
| `User` | The account row. Email unique, password hashed (bcrypt 12). | `status` controls login. Deleting a user cascades through every owned table. |
| `RefreshToken` | One row per active session. `tokenHash` is sha256 of the issued token; the plaintext refresh leaves the server only at issue and rotation. | A row is "alive" iff `revokedAt IS NULL AND expiresAt > now()`. Successful refresh always revokes the old row + inserts a new one (rotation). |
| `UserProfile` | Locale, timezone, currency, soft preferences, onboarding completion timestamp. | One row per user (`userId @unique`). Defaults are `vi` / `Asia/Ho_Chi_Minh` / `VND`. |

### AI credentials

| Model | Purpose | Key invariants |
|---|---|---|
| `UserAiKey` | The user's encrypted OpenAI key + display affordances. | `encryptedApiKey` is a packed `v1:gcm:<iv>:<tag>:<ct>` string produced by `EncryptionService.seal()`. `apiKeyLast4` and `maskedApiKey` are pre-rendered at write time so reads never need decryption to display. The plaintext key never lives in this table. |

### Finance

| Model | Purpose | Indexes |
|---|---|---|
| `Wallet` | A simple money bucket. Soft-deletable. One default per user (enforced in app code, not DB). | `(userId)`, `(userId, deletedAt)`. |
| `Expense` | A spend entry tied to a wallet. Soft-deletable. Idempotency-key-aware. | `(userId)`, `(userId, expenseDate)`, `(userId, deletedAt)`, `(walletId)`, plus `@@unique([userId, idempotencyKey])` so the same Quick Capture can't double-insert. |
| `Income` | An incoming entry tied to a wallet. Same shape as Expense. | Same. |

`onDelete: Restrict` on `walletId` for Expense/Income — you can't drop a wallet
that has rows; soft-delete it instead.

### Tasks

| Model | Purpose | Indexes |
|---|---|---|
| `Task` | Single-shot todo. Recurring tasks are out of MVP. | `(userId)`, `(userId, status)`, `(userId, dueAt)`, `(userId, deletedAt)`. |

### Health journal

| Model | Purpose | Indexes |
|---|---|---|
| `MealLog` | What the user ate, optional cost. | `(userId)`, `(userId, loggedAt)`. |
| `SleepLog` | Sleep window + computed duration. `quality` optional. | `(userId)`, `(userId, sleepAt)`. |
| `MoodLog` | Mood + energy snapshot. | `(userId)`, `(userId, loggedAt)`. |

### Planner

| Model | Purpose | Constraints |
|---|---|---|
| `DailyPlan` | One row per user per day. | `@@unique([userId, date])` — UPSERT-friendly. `date` is `@db.Date` (no time). |
| `DailyPlanItem` | A scheduled block inside a plan. | `(userId)`, `(dailyPlanId)`, `(userId, status)`. The `userId` is denormalised so "all my plan items today" is one indexed scan. |

### AI conversation + assistant

| Model | Purpose | Notes |
|---|---|---|
| `AIConversation` | A chat thread. | `(userId)`. |
| `AIMessage` | Each message in a thread. | `(conversationId, createdAt)` for chronological reads. Role is the standard `USER` / `ASSISTANT` / `SYSTEM`. |
| `AIRecommendation` | A proactive nudge generated by the assistant. `evidence` JSON captures what it looked at. | `(userId, status)` for "show me new ones", `(userId, type)` for filtering. |
| `AiUsageLog` | One row per AI call (capture, recommend, chat…). | `(userId, createdAt)` for per-user billing-style aggregates; `(feature, createdAt)` for cross-user feature analytics. Holds no secrets. |

### Privacy + notifications

| Model | Purpose |
|---|---|
| `PrivacySetting` | Per-source toggles for what the AI is allowed to see (finance / health / meals / tasks / memory / proactive). One row per user. |
| `NotificationSetting` | Per-channel toggles (task / meal / sleep / finance / assistant) plus quiet hours. One row per user. |

Both are upserted at user-creation time with the spec defaults.

### Quick Capture

| Model | Purpose |
|---|---|
| `QuickCapture` | The raw text + `parsedActions` JSON returned by the parser. Status walks `DRAFT → CONFIRMED` (insert into the matching feature table) or `DRAFT → CANCELLED`. Kept after confirmation as an audit trail of how a row was created. |

## Cascade rules summary

```
User
 ├── RefreshToken          → CASCADE
 ├── UserProfile           → CASCADE
 ├── UserAiKey             → CASCADE
 ├── PrivacySetting        → CASCADE
 ├── NotificationSetting   → CASCADE
 ├── Wallet                → CASCADE
 │    ├── Expense          → RESTRICT (soft-delete the wallet first)
 │    └── Income           → RESTRICT
 ├── Expense               → CASCADE
 ├── Income                → CASCADE
 ├── Task                  → CASCADE
 ├── MealLog / SleepLog / MoodLog → CASCADE
 ├── DailyPlan             → CASCADE
 │    └── DailyPlanItem    → CASCADE (also from User directly)
 ├── AIConversation        → CASCADE
 │    └── AIMessage        → CASCADE
 ├── AIRecommendation      → CASCADE
 ├── AiUsageLog            → CASCADE
 └── QuickCapture          → CASCADE
```

A `DELETE FROM "User" WHERE id = ?` is sufficient to discharge a
right-to-erasure request. No tombstones in MVP.

## Decimal handling

Use `Prisma.Decimal` for arithmetic on the API side; cast with `.toString()`
when serialising over the wire (prevents JSON precision loss). The mobile
client treats every money value as an integer of the smallest unit (đồng for
VND) — see [`packages/shared`](../packages/shared) for the conversion helpers
when they land in round 2.

Never:
```ts
amount * 1.1            // float coercion
parseFloat(amount)      // ditto
```

Always:
```ts
new Prisma.Decimal(amount).mul(1.1)
```

## Seed

`apps/api/prisma/seed.ts` is idempotent (uses `upsert` for singletons,
`deleteMany` + `createMany` for collections). It refuses to run when
`NODE_ENV=production`.

After a seed:

| Table | Demo rows |
|---|---|
| `User` | 1 (`demo@lifeos.local` / `demo-password-1234`) |
| `UserProfile` / `UserAiKey` / `PrivacySetting` / `NotificationSetting` | 1 each |
| `Wallet` | 1 default ("Ví chính", VND) |
| `Expense` | 9 across last 7 days, mixed categories |
| `Income` | 1 (monthly salary) |
| `Task` | 6 (mix of TODO / IN_PROGRESS / COMPLETED) |
| `MealLog` | 4 (today's breakfast/lunch/snack + last night dinner) |
| `SleepLog` | 2 (last 2 nights) |
| `MoodLog` | 1 (this morning) |
| `DailyPlan` + `DailyPlanItem` | 1 plan + 5 items for today |
| `AIConversation` + `AIMessage` | 1 thread + 2 messages |
| `AIRecommendation` | 3 (FINANCE / SLEEP / TASK) |
| `AiUsageLog` | 2 |
| `QuickCapture` | 1 DRAFT (a parsed task awaiting confirm) |

The seed `UserAiKey` is **deliberately not a real OpenAI key**. The
`encryptedApiKey` is the literal string `v1:gcm:DEMO_IV:DEMO_TAG:DEMO_CIPHERTEXT`,
`isActive: false`. Any code path that tries to use it must bail with a
clear error rather than silently trying to decrypt.

## Operating commands

```bash
# Inside apps/api
npx prisma migrate dev --name <change>     # create + apply a new dev migration
npx prisma migrate reset --force --skip-seed  # nuke + re-apply all migrations
npx prisma migrate deploy                   # production: apply pending migrations
npx prisma db seed                          # run prisma/seed.ts
npx prisma studio                           # GUI on http://localhost:5555
```

From the repo root, use the workspace shortcuts:

```bash
npm run db:migrate:dev
npm run db:migrate           # = migrate deploy
npm run db:seed
npm run db:studio
npm run db:reset             # destructive — wipes the dev DB
```
